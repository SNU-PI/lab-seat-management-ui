# 연구실 자리 관리

연구실 배치도, 좌석 점유 상태, 시간 제한을 관리하는 Express 앱입니다. 기존 배치도는 `seed/rooms.json`에 초기값으로 들어 있습니다. 첫 실행 후 변경된 상태는 로컬에서는 `data/rooms.json`, Vercel에서는 Vercel Blob에 저장됩니다.

## 로컬 실행

Node.js 20 이상을 권장합니다.

```bash
npm ci
ADMIN_KEY='긴-임의의-비밀값' npm start
```

`http://localhost:3000`에서 현황판, `/admin`에서 배치도 편집기를 볼 수 있습니다. `npm test`는 저장·좌석 전환 등 핵심 동작을 확인합니다. 로컬에서 Blob 설정 없이 실행하면 `data/rooms.json`을 사용합니다. 이 파일은 Git에 포함되지 않습니다.

## Vercel 배포

1. 이 저장소를 Vercel에 연결합니다. 루트 디렉터리는 저장소 최상위로 두고 프레임워크는 `Other`를 선택합니다. 별도의 빌드 명령은 필요하지 않습니다.
2. Vercel Storage에서 **Private Blob** 저장소를 만들고 프로젝트에 연결합니다. 연결하면 `BLOB_READ_WRITE_TOKEN`이 프로젝트 환경 변수에 추가됩니다. 초기 배포 뒤에 연결했다면 다시 배포합니다.
3. 프로젝트의 Environment Variables에 나머지 값을 설정하고 배포합니다.

| 이름 | 설명 |
| --- | --- |
| `BLOB_READ_WRITE_TOKEN` | Private Blob 저장소 연결 시 자동으로 추가되는 토큰 |
| `ADMIN_KEY` | 기본값 `admin`이 아닌 긴 임의의 비밀값 |
| `RESET_HOUR` | 선택 사항. 기본 `2` (한국 시각 02:00) |

Blob 토큰과 어드민 키는 Git에 넣지 마세요. Vercel에서 Blob 연결이나 어드민 키가 없으면 함수가 시작되지 않도록 했습니다. 미리보기와 프로덕션이 같은 Blob 저장소를 쓰면 좌석 상태도 공유하므로, 미리보기가 필요하면 별도 저장소를 연결하세요.

Vercel 배포 뒤 `/api/rooms`에서 JSON 데이터가 보이는지 확인하고, `/admin`에서 키를 입력해 저장한 뒤 새로고침해 변경이 유지되는지 확인하세요. 좌석 링크 `/toggle/<방>/<번호>`를 열면 사용 중과 공석이 전환됩니다.

`/api/rooms`나 좌석 링크에서 저장소 오류가 나오면 Vercel 프로젝트의 Storage에서 **Private Blob** 연결과 `BLOB_READ_WRITE_TOKEN`의 배포 환경 범위를 확인하세요. 저장소를 연결하거나 환경 변수를 수정한 뒤에는 새로 배포해야 합니다. 배포별 URL은 예전 환경 설정을 계속 사용하므로 프로젝트의 최신 배포 주소로 확인하세요. 응답의 `code`와 Vercel Runtime Logs를 함께 보면 접근 거부, 저장소 없음, 사용량 제한을 구분할 수 있습니다.

## 동작과 운영

- `/`는 전체 현황, `/room/1`과 `/room/2`는 각 방의 현황입니다. 화면은 5초마다 최신 상태를 읽습니다.
- `/admin`에서 배치도와 좌석 번호·이용 요일/시간을 수정하고 백업 JSON을 내보내거나 불러올 수 있습니다.
- 같은 좌석 링크를 다시 열면 퇴실 처리됩니다. 좌석 링크를 아는 사람은 누구나 전환할 수 있으므로 링크 공유 범위를 관리하세요.
- 좌석 이용 요일·시간과 매일 `RESET_HOUR` 초기화는 서버 위치와 관계없이 한국 시각(`Asia/Seoul`) 기준입니다. 초기화 시각 이후 첫 요청에서 모든 좌석을 공석으로 돌립니다.
- Blob의 첫 초기화에만 `seed/rooms.json`을 사용합니다. 배포 후 seed를 수정해도 기존 Blob 데이터는 덮어쓰지 않습니다. 초기 배치도를 다시 적용하려면 `/admin`의 백업 불러오기 기능을 사용하세요.
- 좌석 상태는 Private Blob 파일 하나에 저장합니다. 동시 수정 시 파일 버전을 검사하고 충돌하면 재시도합니다. 사용량은 Vercel Blob의 무료 제공량과 요금 정책을 따르므로 운영 전 현재 한도를 확인하세요.
- 로컬 백업 데이터 `data/rooms.json`과 `data/rooms.backup.json`은 저장소에 포함되지 않았습니다. ZIP에 있던 배치도 중 점유자 정보가 비어 있는 `rooms.json`만 seed로 사용했습니다.
